# RC-09 — v0.1.0-rc.1

## Objective

Prepare and publish the first Nexus v0.1 release candidate from a fully validated `main` commit.

## Release identity

- Composer package: `nexus/framework`
- Git tag: `v0.1.0-rc.1`
- GitHub Release title: `Nexus Framework v0.1.0-rc.1`
- Release type: prerelease
- Minimum PHP: 8.4
- Supported quality matrix: PHP 8.4 and PHP 8.5

Composer intentionally has no hard-coded `version` field. The version is derived from the Git tag.

## Prepared artifacts

- `CHANGELOG.md`
- `docs/releases/v0.1.0-rc.1.md`
- `docs/RELEASE_PROCESS.md`
- `.github/workflows/package-smoke.yml`
- `.github/workflows/release.yml`
- Composer homepage/support/archive metadata

## Publication

Publication is performed by the explicit `Release` GitHub Actions workflow after RC-09 is merged to `main`.

Inputs:

```text
version: v0.1.0-rc.1
prerelease: true
```

The workflow re-validates the package, creates an annotated Git tag and publishes the GitHub prerelease using `docs/releases/v0.1.0-rc.1.md`.

## Packagist

GitHub tagging and Packagist registration are separate concerns. The repository/package metadata is prepared for Packagist, but the first registration of `nexus/framework` must be verified after the tag exists. Until Packagist indexing is confirmed, users can consume the tagged repository through Composer VCS configuration.

## Completion rule

RC-09 is complete only after:

1. this preparation PR is merged;
2. the exact `main` release commit passes all required gates;
3. tag `v0.1.0-rc.1` exists and points to that commit;
4. the GitHub Release exists and is marked prerelease;
5. published-package installation is verified.
